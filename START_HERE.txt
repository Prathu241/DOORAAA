🎓 IMPORTANT CONCEPTS
════════════════════════════════════════════════════════════════════════════════

DORA System Architecture:

    ┌─ ESP32-S3 Microcontroller
    │  ├─ Audio Capture (I2S driver)
    │  ├─ TensorFlow Lite Model (keyword detection)
    │  └─ WiFi & WebSocket (communication)
    │
    ├─ INMP441 Digital Microphone
    │  └─ 16 kHz stereo audio input (using left channel only)
    │
    ├─ Dashboard Server (Python/Node.js)
    │  ├─ WebSocket endpoint for audio streams
    │  ├─ HTTP API for telemetry
    │  └─ Web UI for visualization
    │
    └─ Trained TensorFlow Lite Model
       └─ Quantized int8 (~300 KB)


KEY TERMS:

- I2S: Audio interface protocol (3 wires: clock, select, data)
- TFLite: TensorFlow Lite (optimized ML for microcontrollers)
- Quantization: Reducing model size (float32 → int8)
- GPIO: General Purpose I/O pins on microcontroller
- WebSocket: Persistent connection for real-time data
- Latency: Delay from audio to detection result

⚠️ CRITICAL WARNINGS
════════════════════════════════════════════════════════════════════════════════

🔴 DO NOT skip hardware wiring verification:
   Incorrect wiring can damage the microphone or ESP32
   Follow WIRING_STEPS_SIMPLE.txt exactly

🔴 DO NOT skip microphone testing:
   Many issues are easier to diagnose with microphone test first
   Complete Phase 2 before moving to Phase 5

🔴 DO NOT reverse power connections:
   VDD (3.3V) on wrong pin could fry microphone
   Double-check before plugging in USB

🔴 DO NOT unplug USB while uploading:
   Can corrupt firmware, leaving ESP32 unable to update
   Wait for "Upload successful" message

🔴 DO NOT modify GPIO pins without understanding:
   Incorrect pin assignment will break audio capture
   Use GPIO 4, 5, 6 exactly as specified


📞 TROUBLESHOOTING QUICK START
════════════════════════════════════════════════════════════════════════════════

Problem: "COM port not found"
   → Unplug USB, wait 3 seconds, plug back in
   → Check Device Manager for new COM port

Problem: "Upload failed"
   → Check COM port in Tools → Port
   → Try different USB port on computer
   → Try different USB cable

Problem: Serial Monitor shows garbage
   → Check baud rate (bottom-right): should be 9600
   → Click dropdown and select 9600

Problem: Microphone values stuck at 0
   → Check GPIO pins 4, 5, 6 are correct
   → Measure power: VDD-GND should read 3.3V ± 0.1V
   → Try different USB cable for more power

For complete troubleshooting, see: QUICK_COMMANDS.txt

❓ COMMON QUESTIONS
════════════════════════════════════════════════════════════════════════════════

Q: Can I use a different microphone?
A: Need I2S digital microphone (not analog). INMP441 is recommended.

Q: Can I use Arduino Uno instead of ESP32-S3?
A: No. Arduino Uno doesn't have WiFi or enough RAM. Need ESP32-S3.

Q: Do I need a specific WiFi network?
A: Need 2.4GHz (not 5GHz). Can use phone hotspot.

Q: Can I deploy without the server?
A: Yes, after Phase 7. Inference runs entirely on ESP32.

Q: How do I add a second keyword?
A: Retrain model with two classes instead of one. See docs/06_Model_Pipeline.md

Q: What if microphone test fails?
A: Check wiring against WIRING_STEPS_SIMPLE.txt. Most common: GPIO pins wrong.
