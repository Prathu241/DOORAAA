================================================================================

Quick Test - Upload & Monitor:
    1. Open Arduino IDE
    2. File → Open → ESP32_MIC_TEST\mic_test.ino
    3. Tools → Board → ESP32-S3 Dev Module

    ✓ Listening for audio...

    samples=8000
    rms=45.2
    peak=105
    ---

Test Microphone:
    1. Silence test (10 sec):  values ~30-60 rms, ~50-100 peak
    2. Speech test (5 sec):    speak "DORA" → rms jumps to 150-400
    3. Clap test (3 sec):      clap loud → peak spikes to 1000+

================================================================================
TROUBLESHOOTING - QUICK FIXES
================================================================================

Problem: "Port not found" in Arduino IDE
    Fix: 
    1. Unplug USB from ESP32
    2. Wait 3 seconds
    3. Plug USB back in
    4. Tools → Port (should see new COM port)

Problem: Serial Monitor shows garbage/corrupted text
    Fix:
    1. Bottom-right of Serial Monitor shows baud rate
    2. Click dropdown and select 9600
    3. Close and reopen Serial Monitor

Problem: Microphone shows only zeros
    Fix:
    1. Check wiring: GPIO 4 (SCK), GPIO 5 (WS), GPIO 6 (SD)
    2. Measure voltage: VDD-GND should be 3.3V ± 0.1V
    3. Try different USB cable (more power)

Problem: WiFi "Authentication Failed"
    Fix:
    1. Double-check WiFi SSID and password (case-sensitive)
    2. Ensure WiFi is 2.4GHz (not 5GHz)
    3. Restart WiFi router
    4. Restart ESP32

Problem: WebSocket "Connection refused"
    Fix:
    1. Verify server is running: python server.js
    2. Find correct IP: ipconfig (IPv4 Address)
    3. Update ESP32 firmware with correct IP
    4. Check Windows Firewall allows port 8765

Problem: Detection rate very low (< 50%)
    Fix:
    1. Check microphone working (PHASE 2 test)
    2. Check model file correct size (~300 KB)
    3. Try different keyword variations (shout vs. whisper)
    4. Move microphone closer (8-20 cm)
    5. Check for background noise

================================================================================
LATENCY MEASUREMENT - Detailed Procedure
================================================================================

Equipment Needed:
    - Smartphone with timer app
    - ESP32 with microphone
    - Dashboard open in browser

Procedure:
    1. Speak "DORA" while looking at phone timer
    2. Note exact time of utterance (start of "D" sound)
    3. Observe dashboard for detection notification
    4. Note exact time when detection appears
    5. Calculate: latency = detection_time - speak_time
    6. Repeat 5 times and calculate average

Expected Results:
    First detection: ~200-300ms
    Average (5 trials): ~250ms
    Range: 100-500ms acceptable

If latency > 500ms:
    - Check WiFi signal strength (RSSI)
    - Check ESP32 CPU usage (telemetry)
    - Check server response time
    - Possible bottleneck: model inference time

================================================================================
PERFORMANCE MONITORING - What to Watch
================================================================================

ESP32 Resources (from telemetry):
    RAM usage: Should stay < 200 KB (max available ~320 KB)
    CPU usage: Should stay < 20% average
    If > 50% CPU: Model might be too complex

Network Stability:
    WebSocket connection: Should stay connected 10+ minutes
    Packet loss: Should be 0%
    Ping time: Should be < 50ms

Detection Quality:
    True positive rate: > 80%
    False positive rate: < 1 per 2 minutes
    Latency: Consistent (not spiking randomly)

Audio Stream:
    Sample rate: 16000 Hz (16 kHz) ✓
    Bit depth: 16-bit PCM ✓
    Channels: Mono (1 channel) ✓
    Frame size: 320 samples = 20ms frames ✓
